# 零售 / 电商岗位证据手册

先以当前 JD 的职能归属为准：零售和电商岗位可能偏客户洞察、商品、定价、增长、库存或履约。本手册不把任一平台、渠道或指标设为通用必需项。

## 适用角色

- Retail / E-commerce Analyst、Customer / Commercial Insights
- Merchandising、Category、Pricing、Growth、Marketplace Analytics
- Inventory、Demand Planning、Fulfilment 或相关运营分析岗位

## JD 信号

- **客户与增长**：funnel、conversion、retention、cohort、CRM、campaign、personalization
- **商品与商业**：assortment、category、pricing、promotion、margin、sell-through
- **库存与需求**：forecast、replenishment、stock cover、availability、markdown
- **渠道与市场**：omnichannel、marketplace、store、web/app、competitor、market trend
- **履约与体验**：order、delivery、returns、service level、customer satisfaction

把 JD 指向的商业杠杆作为主线；不要把所有零售指标塞进同一份简历。

## 优先呈现的证据

1. 说明分析或运营动作所对应的客户旅程、商品周期或订单流程。
2. 展示从市场/客户/交易/库存数据到建议或执行的闭环。
3. 写清负责的渠道、品类、市场、门店或业务单元范围。
4. 若 JD 偏商业，前置定价、促销、组合、需求或利润相关证据。
5. 若 JD 偏运营，前置可用性、履约、退货、库存和流程改善证据。
6. 若 JD 偏洞察，前置研究设计、客户分群、趋势解释和建议采用。
7. 平台、分析软件和零售系统只在真实使用且与 JD 有关时呈现。

## 可量化维度

- 商业：销售额、毛利、客单价、转化率、复购率、促销增量
- 商品：SKU/品类数、sell-through、markdown、缺货率、库存周转
- 客户：样本/客户量、分群覆盖、留存、满意度、退货率
- 运营：订单量、准时率、履约周期、取消率、服务水平
- 范围：市场、渠道、门店、供应商、活动或时间跨度
- 效率：分析周期、人工步骤、响应时间、预测或补货误差

注明口径和观察窗口；只有能证明个人工作与结果关系时才写因果。

## 常见误写与禁编造

- 不把销售自然增长全部归因于分析、活动或模型。
- 不混淆收入、GMV、净销售、利润和毛利，也不混淆转化与流量。
- 不把预测准确率直接写成库存或利润改善，除非存在落地证据。
- 不虚构 SKU、客户、市场、订单规模或商业提升。
- 不假定零售经验自动等于奢侈品、快消、平台或供应链经验。
- 不因 JD 提及某平台、渠道或系统而补写未使用经验。
- 不泄露客户、供应商、价格或其他受限商业信息。
