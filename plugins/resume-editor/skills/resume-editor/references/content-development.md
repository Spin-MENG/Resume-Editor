# Evidence-Based Content Development

Use this reference to turn sparse resume facts into richer, auditable content. Expand only from candidate-provided evidence; ask for missing detail instead of guessing it.

## Expand evidence across seven dimensions

Map each priority experience or project before drafting. Treat every unsupported element as missing, not implied.

| Dimension | Capture only verified detail |
| --- | --- |
| 1. Context or problem | State the operating setting, trigger, constraint, or need. |
| 2. Objective | State the intended change, question, target, or success criterion. |
| 3. Action and ownership boundary | Separate what the candidate led, owned, executed, supported, or contributed from team work. |
| 4. Method or tools | Name the process, analysis, system, or tool actually used; do not infer proficiency. |
| 5. Scope or cadence | Add verified volume, coverage, duration, frequency, geography, or complexity. |
| 6. Stakeholders or deliverable | Name the audience, collaborators, customer, output, or handoff. |
| 7. Verified outcome or decision use | State a measured result or supported qualitative effect, adoption, decision, or next action without upgrading causality. |

Combine the strongest supported dimensions; do not force all seven into one bullet. Preserve source spans for each detail.

## Run one clarification pass

Identify the missing dimensions that would most improve JD relevance, ownership clarity, or outcome evidence. Ask no more than six questions in one batch, make each question answerable, and tie it to a specific role or project. Prioritize questions such as:

1. What problem, request, or constraint prompted this work?
2. What were you expected to achieve, answer, or deliver?
3. Which parts did you personally own, and which did you support with others?
4. What process, tools, or analysis did you use, and why?
5. What verified scale, cadence, duration, or coverage can you confirm?
6. Who used the deliverable, and what verified result, decision, or follow-up did it enable?

Do not ask the candidate to estimate a metric or select a stronger-sounding claim. If the candidate replies that answers are unavailable, continue with supported details and list the evidence gap outside the polished resume.

### Enforce the clarification gate

In an interactive task, return the question batch without a final import JSON when either condition applies:

- the priority role has fewer than three distinct supported contributions; or
- missing detail leaves at least two Required/Core JD items unresolved.

Wait for the answers, update the evidence ledger, and only then produce the polished draft. Do not treat “proceed,” “optimize this,” or another generic action request as permission to skip questions. Bypass the gate only when the user explicitly requests no questions or an immediate best-effort draft. In that bypass case, do not pad the resume; deliver supported content and list gaps separately.

## Draft in two passes

### Pass 1: Build content-complete evidence

- Draft a candidate bullet bank before enforcing the page limit.
- Give each bullet one contribution: precise action + object, then the most useful verified context, method, scope, stakeholder, deliverable, or outcome.
- Cover different contributions within an entry, such as diagnosis, execution, coordination, delivery, or decision support.
- Keep ownership, tense, seniority, and causality aligned with the source.

### Pass 2: Prioritize for one page

- Rank bullets by JD relevance, evidence strength, recency, impact, and uniqueness.
- Keep the strongest direct evidence first; use transferable evidence only in its real context.
- Compress filler and repeated setup before removing substantive evidence.
- Remove low-relevance duties, weaker variants, and unsupported detail until the A4 preview fits.

## Use practical density targets

Treat these as defaults, then adapt to available evidence and page fit:

- **Profile:** Use 2–3 compact lines or about 35–60 words; state target fit and 2–3 verified differentiators without generic traits.
- **Current role:** Use 3–5 bullets of roughly 16–30 words; allocate the richest and most relevant evidence here.
- **Previous role:** Use 2–3 bullets of roughly 14–28 words; retain distinct, transferable proof and trim routine duties.
- **Projects:** Keep 1–3 relevant projects and use 1–2 bullets of roughly 14–28 words per project; show purpose, personal contribution, method, and deliverable or outcome when supported.

Do not pad thin evidence to meet a count. Prefer fewer specific bullets over more vague bullets.

## Keep every bullet distinct

- Assign one unique contribution or proof point to each bullet.
- Merge or keep only the stronger version when two bullets repeat the same action, deliverable, tool, stakeholder, or outcome.
- Repeat a capability only when a different context demonstrates meaningfully different scope, method, or result.
- Let the profile synthesize the evidence; do not copy experience bullets into it.
- Vary verbs only when the verb remains factually exact; never upgrade “supported” to “led” for variety.

## Replace missing metrics with supported specificity

Use a number only when the candidate confirms it. When metrics are absent, add verified qualitative specificity through the deliverable, audience, cadence, constraint, workflow change, adoption, decision use, or observable outcome. Prefer “prepared weekly exception reports used in replenishment decisions” over “improved efficiency” only when every added detail is sourced. Omit unsupported magnitude, ranking, speed, savings, and causal claims.

## Run the final richness check

- Trace every added element to a candidate source or remove it.
- Ensure each priority entry covers several canvas dimensions across its bullets when evidence permits.
- Ensure each bullet contains a concrete action and object plus at least one useful supported detail.
- Confirm that ownership boundaries and outcome language remain exact.
- Confirm that bullets add distinct evidence and do not restate the profile or one another.
- Surface the strongest JD-relevant proof early and remove generic filler.
- Resolve every `[待确认：…]` marker or omit the unresolved claim before export.
