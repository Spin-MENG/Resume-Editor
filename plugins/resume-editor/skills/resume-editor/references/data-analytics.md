# 数据分析 / 商业智能岗位证据手册

先以当前 JD 的职责、业务场景和措辞为准。本手册用于判断哪些真实经历值得前置，不把任何软件、行业或工作方法视为默认门槛。

## 适用角色

- Data Analyst、Business Intelligence Analyst、Reporting Analyst
- Customer、Marketing、Operations、Finance、Product Analytics 等业务分析岗位
- 职责核心为取数、指标、洞察、报告或决策支持的相邻岗位

## JD 信号

- **指标与报告**：KPI、dashboard、self-service、weekly/monthly reporting、single source of truth
- **分析与决策**：trend、driver、segmentation、forecast、experiment、recommendation
- **数据基础**：query、data model、data quality、governance、automation
- **协作交付**：requirements、stakeholder、executive communication、enablement
- **业务语境**：用 JD 的收入、成本、客户、产品或运营目标决定证据优先级

## 优先呈现的证据

1. 先写业务问题、决策对象或指标，再写分析方法。
2. 展示从数据获取、定义/校验到洞察交付的完整链路。
3. 说明报告、仪表盘或模型由谁使用，以及它改变了什么决策或流程。
4. 若 JD 强调可靠性，前置口径统一、质量检查、可复现性和维护机制。
5. 若 JD 强调影响力，前置跨职能澄清需求、解释结论和推动采用的证据。
6. 工具只在真实使用且与 JD 有关时出现；用工具支持证据，不用工具列表替代成果。

## 可量化维度

- 数据规模：记录量、数据源数、业务单元、市场或时间跨度
- 交付规模：报表/指标数量、刷新频率、用户或团队覆盖
- 效率：处理或报告时间、人工步骤、响应周期、节省工时
- 质量：准确率、缺失/重复率、差异率、故障或返工下降
- 业务效果：收入、成本、转化、留存、库存、服务水平等与工作直接相关的指标
- 采用与决策：活跃用户、使用频率、决策周期、被采纳建议数量

只有来源明确的数字才可使用；否则保留定性表述或标记为待确认。

## 常见误写与禁编造

- 不把“制作报表”夸写成“制定战略”，除非确有决策权限和证据。
- 不把相关性写成因果，也不把团队结果全部归于个人。
- 不虚构指标提升、节省金额、用户数量、数据规模或上线范围。
- 不因 JD 出现某工具就声称掌握；相邻工具经验应写为可迁移证据。
- 不只列技术动作；补足问题、受众、结论或业务用途。
- 不制造“ATS 匹配率”或无依据的成熟度评价。
